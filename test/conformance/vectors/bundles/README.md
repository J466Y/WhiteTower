# Bundle vectors

Signed policy bundles for the verification steps of the specification ([section 7.4](../../../../docs/contracts/module-contract-v0.1.md#74-verification)). Every directory is one case:

| File | Content |
| --- | --- |
| `case.json` | What the enforcement point knows: the agent, the bundle reference from its governance state, the active version; and the expected outcome, `activated` or `rejected` with a reason |
| `manifest.json` | The manifest, exactly as signed: RFC 8785 canonical JSON |
| `manifest.jws` | The detached JWS, absent in the `unsigned` case |
| `schema.cedarschema`, `policies/...` | The bundle's files |

`keys.json` holds the keys: the **trusted** key the enforcement point is configured with, and an **untrusted** one used by the `unknown-key` and `forged-key-id` cases.

**These keys are for tests only.** Their seeds are published in `keys.json` and in the generator, so anyone can sign with them. Never configure them anywhere else.

To verify a case as an enforcement point would: trust the key in `keys.json`, build the expectation from `case.json`, run the steps of section 7.4, and compare with `expected`. The files are generated by `bundle_vectors_test.go`; never edit them by hand, since any change breaks their signatures.
