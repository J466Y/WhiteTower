## Goal

Agents built on common frameworks, instrumented with Microsoft AGT, are governed by White Tower. Their policies come from White Tower's signed bundles, a halt from the console stops them in seconds, they fail closed when they lose contact, and every decision reaches the tamper-evident audit log.

**If the P0-05 spike decided no-go on AGT,** this plan targets the fallback instead: a minimal White Tower enforcement point in Python, without AGT. Steps 3, 4 and 6 then plug into the framework hooks directly; everything else is unchanged.

## Context: what AGT is

From the September 2026 research, to be confirmed by the spike:

- AGT is an **in-process library** with no remote control API. Only its Python SDK covers every component.
- Its kill switch is cooperative: in Python, `kill()` rolls back or hands off in-flight steps and runs a registered callback with a 5-second timeout. It does not prove that the process stopped.
- It supports YAML rules, Rego and Cedar. Its newer policy runtime attaches policies to intervention points and is still alpha.
- It emits audit events as CloudEvents 1.0 (`ai.agentmesh.*`) through a pluggable event sink.
- It is in Public Preview with frequent breaking changes, under the MIT license, which is compatible with Apache-2.0.

White Tower supplies what AGT lacks: remote delivery of approved policies, remote halt with confirmation, fail-closed leases and anchored evidence (architecture document, section 6.1).

## Scope

**In:** a Python package (`whitetower-agt`) loaded in the agent process, providing the gate, the policy source, the halt layers, the event sink, identity mapping, framework helpers, observability, conformance, measurements and packaging.

**Out:** changes to AGT itself (upstream contributions are welcome but not required); non-Python agents (a TypeScript adapter is a Phase 2 candidate); a halt path outside the agent process (Phase 2 harness module).

## Deliverables

- `modules/agt/`: the package, its manifest, tests and examples.
- Two example agents (for instance LangGraph and Microsoft Agent Framework) and a `demo-agent` service in the Compose evaluation profile.
- A conformance report, a measurement report and a compatibility matrix (AGT version × adapter version × contract version).

## Steps

### 1. Package skeleton

- `modules/agt/` with a modern Python build (for example `uv` or `hatch`), `ruff`, strict type checking and `pytest`.
- The Python version is the one the pinned AGT requires (AGT's documentation contradicts itself between 3.10 and 3.11).
- AGT is pinned to an exact version. A weekly CI job tests against AGT's latest release, to catch breaking changes early.
- The module manifest from P0-03.

**Done when:** the package builds and its CI runs, including the weekly job.

### 2. Core client

- Python stubs generated by Buf for the module API.
- Token acquisition with `private_key_jwt`, sharing test vectors with the Go helper of P1-05, and a token cache that refreshes early.
- The watch loop runs in a dedicated thread, so it serves both synchronous and asynchronous agents. The lease timer uses the monotonic clock, and reconnection uses jittered backoff.
- `RegisterInstance`, `Acknowledge`, `GetBundle` and `Publish`.

**Done when:** the client connects to a real core, survives core restarts and passes the lease scenarios of the kit.

### 3. Governance gate

Register a hook that AGT evaluates before its own policies at every intervention point (the mechanism is found in S1). It denies, with a reason, when:

- no state has been received yet;
- the lease has expired;
- the agent or the fleet is halted;
- no valid bundle is active.

The gate reads a thread-safe snapshot of the state.

**Done when:** unit tests cover each condition, mirroring the conformance vectors.

### 4. Policy source

When a new bundle reference arrives:

1. Fetch it with `GetBundle`.
2. Verify the JWS signature against the core's bundle keys (trust configured at installation), the file hashes, and that its version is newer than the active one.
3. Build AGT policy objects (Cedar or Rego, as decided in S1) implementing the White Tower combination semantics.
4. Swap them in atomically and acknowledge the activation.

A bundle that fails verification is handled by the P0-03 rule: keep the last valid bundle, never run without one, and raise an alert event.

**Done when:** the kit's bundle scenarios pass (unsigned, tampered, older).

### 5. Halt layers

When the agent or the fleet is halted:

1. **Close the gate at once:** every evaluation is denied.
2. **Call AGT's `kill()`** for active sessions, which runs the framework termination callbacks registered by the helpers of step 8.
3. **Apply the agent's halt mode:**
   - `block`: gate only;
   - `interrupt`: gate plus kill callbacks;
   - `terminate`: all of the above, then the process exits after a grace period (10 seconds by default).
4. **Acknowledge** each layer with its timestamp, honestly, including "interruption not confirmed".

On release, the gate reopens only if the lease and the bundle are valid. A terminated agent is restarted by its supervisor (for example Kubernetes) and starts closed until its state arrives (KIL-07).

**Done when:** the kit's halt scenarios pass, and the measurements of step 11 meet NFR-04.

### 6. Event sink and durable buffer

- Implement AGT's event sink and map `ai.agentmesh.*` events to the White Tower catalog (`decision.made`, `action.executed`, `action.blocked`), keeping the original type in an extension attribute.
- Add the subject (the White Tower agent ID), `wtseq` and the trace context.
- Buffer events durably in a local SQLite file in WAL mode, capped in size and sized for NFR-08 (24 hours at 10 events per second). Publish in batches, with retries and respect for backpressure.
- When the buffer is full, close the gate: no action without evidence.

**Done when:** after a one-hour core outage under load, every event arrives once reconnected, with no gap in `wtseq`.

### 7. Identity mapping

- Configure the correspondence between the White Tower agent ID and AGT's agent identity (a DID).
- Decide whether AGT's `sponsor_email` is filled from the owner (a privacy trade-off: it puts the owner's email in the agent process), or whether a pseudonymous owner ID is used.
- Phase 2: register White Tower's JWKS in AGT's identity provider chain for agent-to-agent verification.

**Done when:** events and decisions carry consistent identities on both sides.

### 8. Framework helpers

Start with the two frameworks of the pilot, for example LangGraph and Microsoft Agent Framework (which has native AGT support); add the OpenAI Agents SDK if the pilot needs it. Each helper:

- makes sure every tool and model call goes through AGT's intervention points;
- registers termination callbacks that cancel running tasks.

The examples live in `modules/agt/examples/`, and the Compose `demo-agent` service uses one of them.

**Done when:** each example runs governed end to end.

### 9. Observability

OpenTelemetry metrics: gate state, remaining lease, active bundle version, buffer depth, halt timings. Logs are structured, and they never include prompts or tool payloads unless explicitly enabled.

**Done when:** the metrics appear in the Compose stack's collector.

### 10. Conformance and end-to-end tests

- Run the conformance kit against the adapter, wrapping a sample agent.
- End-to-end test in Compose: register an agent, approve it and its policy, activate it; the demo agent runs, its decisions reach the audit log; halt it and check the gate closes within target; release and reinstate it.

**Done when:** both run in CI.

### 11. Measurements

Measure, with the pilot's frameworks:

- decision overhead including the gate (NFR-02);
- halt effect: gate closing, in-flight interruption, termination (NFR-04);
- buffer durability during a core outage (NFR-08).

These numbers are evidence for the Phase 1 gate.

**Done when:** the report is in `docs/performance/`.

### 12. Packaging and documentation

- A wheel built in CI, signed with Sigstore, with an SBOM, published under the project's name (for example `whitetower-agt`).
- An installation guide, the compatibility matrix and a troubleshooting section.

**Done when:** a pilot engineer can instrument a new agent from the guide alone.

## Acceptance criteria

- The adapter passes the full conformance suite.
- The end-to-end demonstration runs with two frameworks: decisions in the audit log, halts effective within NFR-03 and NFR-04, and fail-closed within the TTL during a partition.
- Decision overhead within NFR-02 (in-process p99 ≤ 5 ms, gate included).
- The weekly job against AGT's latest release is running.

## Risks and open questions

| Risk or question | Mitigation or owner |
| --- | --- |
| AGT breaking changes between releases | Exact pin, weekly job against its latest release, thin adapter, compatibility matrix |
| AGT's extension points are not enough for the gate or the event sink | Found in S1; fallback enforcement point without AGT |
| Interrupting in-flight calls is unreliable in some frameworks | Halt modes, with `terminate` as the guaranteed option; honest layered acknowledgements |
| Mixing threads and `asyncio` in agent processes | The watch loop is isolated in its own thread; tests in both kinds of agents |

## Notes for implementers

- Keep all White Tower logic outside AGT's code paths except the four hooks; this keeps upgrades cheap.
- The gate check must be cheap (a lock-free read of an immutable snapshot); it runs on every intervention point.
- Treat the core's bundle keys as the adapter's trust root; ship them through configuration, never fetch them over an unauthenticated channel.
