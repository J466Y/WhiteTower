## Goal

The `whitetower` server with all the cross-cutting plumbing in place: configuration, listeners and TLS, logging, metrics and tracing, database and migrations, scaffolding for both APIs, leader-elected background jobs, notifications across replicas, the embedded console and a test harness. After this plan, feature plans only add domain code.

## Scope

**In:** everything listed in the goal, plus the rules that keep the internal packages clean.

**Out:** authentication and authorization logic (P1-03; this plan leaves the hooks), the audit writer (P1-02; this plan leaves the transaction hook), domain features.

## Deliverables

- `cmd/whitetower` and the `internal/platform/...` packages.
- `docs/reference/configuration.md`, generated from code.
- The test harness (database fixture, API client, fake clock) and an end-to-end smoke test in CI.
- `docs/development/internals.md`: package layout and coding rules.

## Steps

### 1. Configuration

One YAML file plus environment overrides prefixed `WT_`, loaded into a typed structure with defaults and validation. Secrets are always read from files (`*_file` keys), never from plain values. `whitetower config print` shows the effective configuration, which holds no secret. The reference documentation is generated from the structure's field comments.

**Done when:** an invalid configuration stops startup with a message naming the field, and the reference is generated in CI.

### 2. Listeners, TLS and shutdown

Three listeners, as in the architecture document: console and API (`:8443`), machine (`:9443`, HTTP/2), operations (`:9090`, cluster-internal).

- TLS certificates are read from files and reloaded when they change, so certificates rotate without restarts. TLS 1.2 is the minimum and 1.3 is preferred.
- A development mode generates self-signed certificates and logs a loud warning.
- On SIGTERM, the server stops accepting connections, sends a "reconnect elsewhere" close to watch streams, and finishes within a deadline shorter than the minimum lease TTL.

**Done when:** tests cover TLS versions, certificate reload and a drain with open streams.

### 3. Observability

- **Logs:** `log/slog` in JSON, with request ID, trace ID and principal ID, and redaction helpers for tokens, keys and cookies.
- **Metrics:** exposed at `/metrics`, prefixed `whitetower_`.
- **Tracing:** OpenTelemetry with W3C propagation. No exporter runs unless one is configured (NFR-14).
- **Health:** `/healthz` for liveness; `/readyz` for readiness (database reachable, migrations applied, signing keys loaded).

**Done when:** a request can be followed through logs and traces by its IDs, and the defaults make no outbound connection (unit test).

### 4. Database layer

- A `pgx` connection pool and `sqlc` generation wired into `task gen`.
- `goose` migrations embedded in the binary and applied by `whitetower migrate` under an advisory lock, so only one replica migrates. It runs before the server: an init container on Kubernetes, a one-off service in Compose. The server waits until the schema is the one its binary expects, and refuses to start if the schema is newer.
- Two connection strings: the migration role's, used only by `whitetower migrate`, and the runtime role's, the only one the server holds ([threat model](../../security/threat-model.md), DC-3).
- A transaction helper, `platform.InTx(ctx, func(tx) error)`, with hooks for audit events (filled by P1-02) and for "after commit" notifications (used by the governance state).
- Apply `00001_init.sql` from P0-02.

**Done when:** two replicas start against an empty database, one migrates while the other waits, and both become ready; the server process holds no migration credentials.

### 5. REST API scaffolding

- The OpenAPI document starts with health and a placeholder `/me`, and `oapi-codegen` generates strict server interfaces.
- Middleware chain: request ID, panic recovery, access log, security headers (HSTS, `X-Content-Type-Options`, `Referrer-Policy`, CSP with `frame-ancestors 'none'`), body size limits, rate limiting (token bucket per principal and per IP), an authentication interface for P1-03 and an authorization hook.
- Helpers for RFC 9457 problem details with stable error codes, cursor pagination, and ETag and If-Match.
- The OpenAPI document is served at `/api/v1/openapi.json`.

**Done when:** a sample endpoint shows every helper working in tests.

### 6. Module API scaffolding

Mount the ConnectRPC handlers generated by Buf on the machine listener, with interceptors for authentication (placeholder until P1-05 and P1-07), logging, metrics, contract version negotiation and panic recovery. Configure HTTP/2 over TLS and keepalives.

**Done when:** a generated client calls a stub method over gRPC and over the Connect protocol with JSON.

### 7. Background jobs

A job registry and runner. Each job takes its own PostgreSQL advisory lock, so only one replica runs it. Jobs run on an interval or a cron schedule. Metrics per job: last run, duration, failures. All time goes through a clock interface, faked in tests.

**Done when:** with two replicas, a test shows each job running on exactly one of them, and running on the other when the first stops.

### 8. Notifications across replicas

A `notify.Bus` interface with a PostgreSQL `LISTEN/NOTIFY` implementation that reconnects and triggers a resynchronization callback after a disconnection, plus an in-memory implementation for unit tests. Payloads carry identifiers and versions only.

**Done when:** a change committed on one replica reaches listeners on the other, and a forced listener disconnection triggers a resynchronization.

### 9. Embedded console

Serve `web/dist` with a fallback to `index.html` for client-side routes. Hashed assets get long-lived immutable caching; `index.html` gets `no-cache`. The strict CSP allows no external origin.

**Done when:** deep links work and the browser loads nothing from outside.

### 10. Test harness

- A PostgreSQL fixture with `testcontainers-go`, reused per package.
- The generated API client for tests.
- A fake clock and a golden-file helper.
- An end-to-end smoke test in CI that starts the Compose stack and checks health, the OpenAPI document and the console.

**Done when:** a new domain package can write an integration test in a few lines.

### 11. Internal rules

Document and enforce with a lint rule (for example `depguard`):

- domain packages never import transport packages;
- every state-changing operation runs inside `InTx` and records audit events there;
- dependencies are wired explicitly in `cmd/whitetower/main.go`, with no dependency injection framework and no global state.

**Done when:** the rules are documented and CI fails when they are broken.

## Acceptance criteria

- `whitetower migrate` prepares the database, then the server starts from its configuration and serves health, metrics, the OpenAPI document and the console on the right listeners with TLS. The end-to-end smoke test is green.
- With two replicas on one database, each job runs on exactly one replica, and notifications reach the other replica (tests).
- Graceful shutdown completes within the configured deadline with open streams (test).
- With default settings, the server makes no outbound connection (unit test here; full egress test in P1-12).
- The security tests assigned to this plan in the [security test catalog](../../security/security-tests.md#p1-01-core-platform-skeleton) pass: ST-01 to ST-05.

## Risks and open questions

| Risk or question | Mitigation or owner |
| --- | --- |
| Building a framework instead of a product | Only add an abstraction when a Phase 1 plan needs it; review against this rule |
| HTTP/2 and gRPC behave differently behind some load balancers | Test the machine listener behind the ingress used in P1-12 early |

## Notes for implementers

- Go's `net/http` pattern routing (Go 1.22 and later) is enough; no router library is needed.
- Keep `context.Context` as the first parameter everywhere; carry the principal and request ID in it through typed keys.
- `LISTEN/NOTIFY` needs a dedicated connection outside the pool; it does not work through PgBouncer in transaction mode (documented in P1-12).

### 2026-09-30: configuration, commands and listeners

- `internal/platform/config`: defaults, then a YAML file that refuses unknown keys, then `WT_` variables; every error names its setting. The [configuration reference](../../reference/configuration.md) is generated from the field comments, and a test fails when it is out of date.
- `whitetower serve`, `config print`, `healthcheck` and `version`, on cobra. The container images run `serve`, listening on every interface.
- Three listeners: console and API on 8443 and the module API on 9443, both HTTPS with HTTP/1.1 and HTTP/2; operations on 9090, plain HTTP, with `/healthz` and `/readyz`. They bind to the loopback interface by default.
- `internal/platform/servertls`: certificates reloaded when their files change, the last good one kept when a new one does not load; TLS 1.2 at least. `dev.self_signed_tls` generates a certificate at startup and logs a warning.
- Shutdown: the drain signal ends long-lived streams, `/readyz` answers 503, and what is still open at the deadline (8 s by default, always under 10 s) is closed.
- `wtctl --insecure-skip-tls-verify`, for development servers; it warns when used.
- Tests: TLS versions, certificate reload, a drain with open streams, the deadline, and the module API over gRPC and Connect. The Compose stack, the end-to-end tests and the browser test use HTTPS.
